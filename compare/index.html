The short version

What Purlo actually is

Purlo is a single API endpoint that takes an image (uploaded, or fetched from a URL) and returns a web-safe one — resize, format-convert, compress and strip metadata, chained in one call. It is deliberately narrow: it is not a CDN, not a digital-asset manager, and it doesn't host your media. That narrowness is the point — it's why it's cheap, why it integrates in minutes, and why there's nothing to learn beyond one operations object.

The comparison below is honest about the trade-off: the big platforms do far more than Purlo, and sometimes that "more" is exactly what you need. When it isn't, you're paying in price and complexity for breadth you'll never touch.

Reach for Purlo when…

  • You accept user uploads and need them resized, converted and cleaned before you store or show them.
  • Privacy matters — you want EXIF/GPS gone by default, and images that are never persisted on someone else's disk.
  • You want a flat, predictable bill — a few pounds a month, not usage credits to model.
  • You're a solo dev or small team who wants to be done in ten minutes.

Pick a bigger platform when…

  • You need a media CDN that transforms and delivers images on-the-fly from a URL at scale.
  • You want video, a digital-asset manager, or AI features like smart cropping and tagging.
  • You want the platform to store and serve your whole media library, not just process it.
  • You have the traffic and budget to make a full platform's per-feature depth pay off.

The real competitor

Purlo vs rolling your own with sharp

Be honest about the true alternative: for many teams it isn't Cloudinary — it's npm install sharp and a few lines of code. sharp (libvips) is excellent, free, and does everything Purlo does under the hood. If you have the time and the infrastructure, DIY is the cheapest option there is, and we'd genuinely tell you to use it.

What you take on when you DIY is the un-fun part that doesn't show up in the happy path: capping upload bytes and pixel counts so a decompression bomb can't OOM your box; a processing timeout and concurrency limit so a burst of large images doesn't peg the CPU and take your health check down; and — if you accept a URL to fetch — SSRF protection so nobody points your fetcher at 169.254.169.254 or your internal network. Purlo has all of that built in and maintained. You're not paying for the resize; you're paying to never think about those edge cases.

resize → webp → strip, in one call 
# 800px wide, WebP q80, EXIF/GPS stripped, ICC kept
curl -X POST https://api.purlo.dev/v1/image \
  -H "Authorization: Bearer purlo_YOUR_KEY" \
  -F 'operations={"resize":{"w":800},"format":"webp","quality":80,"strip":true}' \
  -F "image=@photo.jpg" \
  -o out.webp

Questions developers actually ask

FAQ

What's the cheapest way to resize and strip EXIF from user uploads?

If you can run infrastructure, rolling your own with sharp (libvips) is the cheapest — it's free and fast, you just own the resource-limit and SSRF hardening yourself. If you'd rather not run a pipeline, a hosted API is the low-effort route; Purlo starts free (1,000 images/month, no card) and £5/month for 5,000, and does resize + convert + compress + strip in a single call.

Is Purlo a good Cloudinary alternative for a small project?

For a small project that just needs to clean and resize uploads, yes — that's exactly the gap Purlo fills, at a flat few pounds a month with no usage credits to model. If you need a full media CDN, video, or a digital-asset manager, Cloudinary and ImageKit do far more; Purlo deliberately doesn't. See the comparison table above for the trade-off.

Does Purlo store the images I send it?

No. Purlo is stateless — every image is processed in memory or a temp path and deleted the moment the response is sent. It keeps accounts, API keys and usage counts, never image data. That's both a privacy feature and the reason it stays simple to run.

Does stripping metadata ruin the colours?

It can, if you strip the ICC colour profile along with the EXIF — the image then looks flat because viewers fall back to assuming sRGB. Purlo strips EXIF and GPS by default but keeps the ICC profile, so colours stay correct while the privacy-sensitive metadata is gone.

Can I convert images to WebP or AVIF?

Yes. Set "format": "webp" or "avif" (also jpeg and png) in the same call as your resize and compression. The operations apply in a fixed, documented order and return the finished image.

How is Purlo different from imgix or a CDN?

imgix and similar services are real-time image CDNs: you transform and deliver images by appending parameters to a URL, and they cache and serve them. Purlo is a processing step, not a delivery layer — you POST an image and get the processed bytes back to store or serve however you like. If your need is fast on-the-fly delivery at scale, a CDN is the right tool; if it's cleaning uploads server-side, Purlo is simpler and cheaper.
